# Семантика v0.1

Единица времени — условная минута (`time_unit: minute`). `NaN`, бесконечности и неположительные длительности запрещены. Допуск сравнения времён: `1e-9`. Одинаковый результат бит-в-бит между разными CPU не обещается; порядок событий обязан совпадать.

## Экземпляр

`FactoryInstance` неизменяем. Идентификаторы — строки `[A-Za-z0-9][A-Za-z0-9_.:-]*`. Индекс операции в действии — это позиция в порядке заданий, затем в списке операций задания. Внутренний индекс не заменяет строковый id.

В v0.1:

- у станка `capacity = 1`;
- `release_time` каждого задания равен 0;
- маршрут задания — одна цепочка. Пустые `predecessor_ids` означают порядок списка. Явные предшественники тоже должны давать одну цепь без ветвлений;
- flow shop дополнительно требует один и тот же порядок станков у всех заданий, без повтора станка в маршруте.

`due_date: null` исключает задание из `total_tardiness` и `weighted_tardiness`. Если due date нет ни у одного задания, оба поля равны `null`, а не нулю.

## События

Приоритет (меньше — раньше) при равном времени:

| Событие | Приоритет |
|---|---|
| `operation_finish` | 10 |
| `job_release` | 20 |
| `operation_start` | 30 |
| `decision_required` | 40 |
| `episode_end` | 50 |

Третье поле ключа — монотонный `sequence`. Он назначается в момент постановки в очередь, поэтому в журнале обработки номер может быть меньше у более позднего по времени события: финиш планируется в момент старта.

Агент вызывается только в точке решения: есть хотя бы одна готовая операция, чей станок свободен, и все события текущего времени уже обработаны. Одно действие запускает одну операцию. Если после этого снова есть кого запускать, следующее решение происходит в то же время.

Если запускать некого, а в очереди есть будущее событие, время перематывается без вопроса агенту. `WAIT` при `allow_voluntary_idle=false` запрещён. При `true` `WAIT` обязан перейти к строго более позднему событию. Нулевой цикл ожидания не допускается.

Если очередь пуста и работы не закончены, эпизод завершается с `termination_reason="deadlock"` и `success=false`. Это не успешный `terminated`. В классическом job shop v0.1 такой исход означает ошибку модели или симулятора, а не обычный план.

`terminated=true`, `success=true`, `termination_reason="completed"` — все операции завершены. `truncated=true` — исчерпан горизонт, бюджет событий или бюджет решений. Оба флага одновременно не ставятся.

## Награда и метрики

По умолчанию каждый переход даёт `-delta_sim_time / time_scale`. Сумма при `gamma=1` на успешном эпизоде с `t=0` равна `-makespan / time_scale`.

`terminal_makespan` отдаёт 0 до конца и `-makespan / time_scale` на успешном последнем шаге. Неуспех в обоих режимах дополнительно вычитает `failure_penalty` (по умолчанию 0).

`makespan` заполняется только когда завершены все задания. Метрики считаются по интервалам движка, не по награде. `simulation_wall_seconds` пишет бенчмарк снаружи: внутри `info` процессорного времени нет, иначе Gymnasium не смог бы проверить детерминизм `info`.

## Наблюдение `obs_v1`

Времена делятся на `time_scale`. Нет due date или горизонта — признак `-1`. Будущих случайных событий в v0.1 нет, и в вектор их класть нельзя. Длительности известны: экземпляр статический.

Признаки станка: idle, busy, остаток текущей операции, занятость с учётом незавершённого куска, сумма длительностей незавершённых операций этого станка, число готовых операций на него.

Признаки операции: четыре флага статуса, длительность, остаток, время ожидания в READY, нормированные индексы станка и задания, позиция в задании, due date, приоритет, флаг «можно запустить сейчас».

Глобальные: текущее время, горизонт, доли завершённых операций и заданий, доля запускаемых операций, средняя загрузка.

`action_mask` лежит в `info` и в `env.action_masks()`. Последний индекс дискретного пространства — `WAIT`. `sample()` возвращает действие, допустимое в **начальной** точке эпизода: так устроен проверяльщик Gymnasium, который берёт действие, затем делает `reset` и применяет его. `step` всё равно проверяет живую маску.
