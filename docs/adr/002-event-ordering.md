# ADR-002. Порядок событий и решений

Статус: принято для v0.1.

При равном времени сначала финиши, затем выпуски заданий, затем старты, затем маркер решения, затем конец эпизода. Приоритеты: 10, 20, 30, 40, 50.

Все события текущего времени обрабатываются до запроса действия. Несколько свободных станков дают несколько решений с нулевой длительностью, по одному запуску за `step`. Число таких решений ограничено числом готовых операций и `max_decisions_per_episode`.
