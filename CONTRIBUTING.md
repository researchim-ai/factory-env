# Участие в разработке

FactoryRL сравнивает политики на фиксированной семантике. Изменение порядка событий, награды или признаков наблюдения без нового идентификатора среды ломает воспроизводимость.

## Локально

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
ruff check src tests examples
ruff format --check src tests examples
mypy src
pytest
```

## Что прикладывать к изменению

- Затронутый идентификатор требования (`FR-*`, `NFR-*`, `SEC-*`, `AC-*`), если он есть.
- Тест на новое поведение. Для ядра — ещё и проверку инварианта или золотого следа.
- Запись в `CHANGELOG.md`, если меняется публичное поведение.
- ADR в `docs/adr/`, если меняется порядок событий, наблюдение, награда или граница core/RL.

## Чего не делать

- Не подменять недопустимое действие допустимым молча.
- Не импортировать Gymnasium, PyTorch или OR-Tools из `factoryrl.core` и `factoryrl.models`.
- Не класть в репозиторий чужие benchmark-файлы без записи источника и лицензии.
- Не утверждать, что политика лучше эвристики, без seed, split, хеша экземпляра и кода прогона.
